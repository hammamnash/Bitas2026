01
The EA Shift

Bringing all domains together

05 min

Customers usually run separate, disconnected tools per domain. EA connects business capabilities, applications, technology, ownership, and initiatives. This shared context makes AI more relevant to the enterprise, while AI can help architects build and use that context faster.

The three core layers + Strategic COntext + Solution Layer
  • BusinessBusiness Capabilities, Organization, Business Context
  • ApplicationApplications, Interfaces, Data Objects
  • TechnologyIT Components, Providers, Tech Categories
  • Strategy & TransformationObjectives, Initiatives, Platforms: the steering layer on top

AI-EA Synergies

EA gives AI context. AI helps EA move faster.

EA → AI: Enterprise context
EA connects business priorities, capabilities, applications, data, technology, and ownership. This context helps teams identify valuable AI use cases, understand dependencies and constraints, and ground AI responses in the organization's architecture.
AI → EA: Faster architecture work
AI can help extract and structure architecture information, suggest relationships for review, and answer questions using repository data. Architects can spend less time assembling information and more time assessing change impacts, evaluating options, and advising decision-makers.

Shared foundation: Current, connected repository data and human validation.

03
Repository · Governance · Data Freshness

Governance & data that stays fresh

10 min

Our answer is useful only when the underlying data is complete, owned, and current. Mandatory attributes support completeness, Quality Seal assigns approval responsibility, history records changes, and surveys help owners refresh the data.

What I show in LeanIX ›
  • Open a fact sheet and read its default attributes.
  • Show the mandatory attributes required before approval.
  • Open the Quality Seal and show who reviews and approves the fact sheet.
  • Open fact-sheet history to show who changed what and when.
  • Create and run a survey, and show the owner’s response flow.
04
Architecture views

Different views of the same architecture

08 min

Choose the view that fits the question: inspect a record, trace dependencies and potential change impacts, explain relationships in a diagram, browse an application catalog, or analyze the portfolio.

Fact Sheets

Inspect one architecture record in detail, then check how its data has changed.

Object Explorer

Start with a selected object and follow its relationships across architecture domains to assess potential change impacts. Trace connections between objectives, initiatives, applications, and technology, then expand related organizations, data, or interfaces. The analysis depends on the relationships recorded in the repository.

Diagrams

Explain how architecture elements connect, and compare saved versions of the drawing.

Portal

Give users a catalog they can browse without starting from a diagram or a detailed architecture record.

  • Search and filter the application catalog.
  • Read application descriptions and availability or approval status.
  • Use the visible request entry point when an application is needed.

Dashboards & Reports

Start from a dashboard organized for a role or use case, then open a report to examine a specific architecture question.

Report example: Technology Lifecycle ›
What I show in LeanIX ›

05
AI Capability & Integration

Give AI enterprise context

10 min

Generic AI does not know your capabilities, applications, dependencies, owners, or initiatives. SAP LeanIX supplies that governed enterprise context to its native AI capabilities and, through MCP, to an external AI harness.

Three jobs for AI

Discover and structure

Inventory Builder analyzes diagrams, images, and files, then proposes fact sheets and relations for an architect to review.

Ask and understand

Use natural language to find architecture facts, relationships, and missing information.

Prompt workbench ›
Run it in LeanIX first, then reuse it in the MCP harness.

Connect and extend

MCP gives an external AI client access to the LeanIX tools allowed for the authenticated user or technical role.

View AI-generated impact brief

Saved MCP result: Salesforce Experience Cloud dependencies, relationship paths, and mapping gaps. Opens in a new tab; no live LeanIX connection is required.

Presenter notes: LeanIX → MCP proof sequence ›
  1. Ask in LeanIXRun the decision-trace prompt in Joule or the LeanIX AI assistant.
  2. Open the evidenceInspect the returned capability, application, IT component, owner, and remediation records.
  3. Ask through the MCP harnessPaste the same prompt into your external AI chat connected to the SAP LeanIX MCP server.
  4. Compare and explain the boundaryBoth paths use governed repository context. MCP exposes only the tools available to the authenticated role, and missing data must remain visible.

Supporting integration paths

LeanIX can combine native connectors, APIs, and spreadsheet exchange to bring source data into the architecture repository.

Use the native connector to exchange selected data with ServiceNow and connect operational records to the architecture model.

Use REST or GraphQL APIs when the source or use case needs a custom integration.

Use Excel import and export for migration, review, or controlled bulk updates.
